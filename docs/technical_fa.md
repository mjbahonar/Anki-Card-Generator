# راهنمای فنی

[شروع سریع](../README_fa.md) · [Technical guide](../TECHNICAL.md)

جزئیات تنظیمات، منابع، تمرین‌ها، کش و نگهداری برنامه. برای ساخت اولین دک، از ریدمی شروع کن.

## تنظیمات در یک فایل

| بخش کانفیگ | چه چیزی را تغییر می‌دهد؟ |
| --- | --- |
| `language` | زبان ورودی: `no` برای نروژی، `en` برای انگلیسی؛ زبان ترجمهٔ گوگل، مثلاً `fa` |
| `input` | نام فایل اکسل، نام یا شمارهٔ شیت، وجود هدر، ستون کلمات، حذف تکراری‌ها، تعداد کلمات |
| `sources.*` | روشن و خاموش بودن دیکشنری‌ها و ترتیب نمایش |
| `audio` | اولویت صوت، کش، لهجهٔ انگلیسی، مسیر ذخیره و کپی اختیاری در پوشهٔ رسانهٔ Anki |
| `output` | مسیر خروجی، نوع فایل‌ها، پیشوند نام و ذخیرهٔ بازیابی |
| `anki` | نام دک، شناسهٔ دک و شناسهٔ مدل |
| `style` | فایل استایل مشترک فعلی |
| `runtime` | زمان انتظار شبکه، تلاش مجدد ترجمه، فاصلهٔ بین کلمات و مرورگر مخفی |
| `info` | متن انگلیسی و لینک پایین کارت |

شمارهٔ شیت و ستون از **صفر** شروع می‌شود. برای انتخاب ستون با نام، `header = true` لازم است. مسیرهای نسبی نسبت به محل فایل کانفیگ حساب می‌شوند.

`runtime.source_timeout_seconds = 30` مهلت مشترک دریافت هر کلمه از هر سورس است؛ تلاش مجدد، صفحات مختلف مدخل و انتظار جدول صرف از همین مهلت استفاده می‌کنند. پس از پایان مهلت، سورس کنار گذاشته می‌شود و پردازش ادامه پیدا می‌کند. مقدار صفر این سقف را غیرفعال می‌کند. `runtime.timeout_seconds = 30` سقف هر عملیات شبکهٔ جداگانه است و برای صوت نیز استفاده می‌شود. بستن منابع و پردازش محلی ممکن است کمی به زمان مهلت شبکه اضافه کند.

برای خاموش کردن یک سورس، زیر بخش آن `enabled = false` بنویس. برای تغییر ترتیب، بخش‌های `[sources.…]` را در فایل جابه‌جا کن؛ هیچ تغییری در کد استخراج یا پکیج Anki لازم نیست. سورس‌های ناسازگار با زبان انتخاب‌شده خودکار رد می‌شوند.

## انگلیسی و نروژی

تنظیم عمومی پیش‌فرض، نروژی با فقط Lexin بوکمال و معنی انگلیسی است؛ منابع دیگر اختیاری‌اند. Lexin دو نتیجهٔ اول را بررسی می‌کند و مدخل‌های دارای عنوان دقیقاً مطابق ورودی را نگه می‌دارد.

برای انگلیسی `language.source` را `en` کن، اکسل مورد نظر را انتخاب کن و سورس‌هایی مثل Oxford، Fastdic، Cambridge، Faraazin و B-Amooz را فعال کن. ترجمهٔ گوگل نیز قابل استفاده است. Dict.com از جفت انگلیسی–نروژی استفاده می‌کند و برای کلمات انگلیسی معنی نروژی می‌دهد؛ برای دک انگلیسی–فارسی آن را غیرفعال کن. فهرست کامل سورس‌ها و محدودیت‌هایشان در [راهنمای انگلیسی](../TECHNICAL.md) آمده است.

برای Fastdic، Cambridge و Oxford تعداد مثال‌های هر معنی با `examples_per_definition` کنترل می‌شود؛ پیش‌فرض سه مثال است و مقدار صفر فقط معنی‌ها را نگه می‌دارد.

صوت خود کلمه دریافت می‌شود؛ صوت شکل‌های جدول Lexin نیز با `table_audio = true` قابل فعال‌کردن است. صوت مثال‌ها و اصطلاح‌ها دریافت نمی‌شود. صوت Lexin اولویت نروژی است و Google TTS جایگزین آن می‌شود. برای انگلیسی Fastdic با لهجهٔ `us` یا `uk` و Google TTS قابل انتخاب‌اند. کش از دانلود دوباره جلوگیری می‌کند. لازم نیست سورس متن یک دیکشنری فعال باشد تا صوتش انتخاب شود.

## دیکشنری‌ها و تصاویر

Oxford تمام نقش‌های دستوری مدخل‌های دقیق همان کلمه را می‌گیرد. Bokmålsordboka و Nynorskordboka دو سورس جدا هستند؛ جدول صرف بازشده و تأکیدهای bold و italic را حفظ می‌کنند. املای Nynorsk ممکن است با Bokmål فرق کند و برای بعضی کلمات مدخل دقیق وجود نداشته باشد.

برای عکس، بخش `[sources.images]` را با `enabled = true` فعال کن. `count = 3` تعداد عکس و `priority = ["google", "commons"]` ترتیب دریافت را تعیین می‌کند. اگر گوگل محدود باشد، تصاویر از Wikimedia Commons دریافت می‌شوند؛ با `["commons"]` فقط Commons استفاده می‌شود. نام پدیدآورنده و اطلاعات مجوز همراه عکس نمایش داده می‌شوند. تصاویر کلمات چندمعنایی را بازبینی کن.

## خروجی‌ها و خطاها

هر ترکیبی از `xlsx`، `csv`، `apkg`، `html` و `json` را در `output.formats` قرار بده. پیش‌نمایش HTML صوت قابل پخش دارد. فایل Anki فقط رسانه‌های استفاده‌شده را در بسته قرار می‌دهد. Info همیشه آخر است.

کنسول وضعیت `OK`، `EMPTY` یا `FAIL` هر سورس، زمان دریافت و وضعیت صوت را نشان می‌دهد. گزارش پایانی تعداد نتایج موفق، خطاها، صوت‌ها و مسیر خروجی‌ها را جمع‌بندی می‌کند.

خطای یک سایت پردازش بقیهٔ منابع و کلمات را متوقف نمی‌کند. گزارش خطا در فایل `*_errors.json` ذخیره می‌شود. ذخیرهٔ بازیابی هر چند کلمه یک CSV می‌سازد؛ مقدار `autosave_every = 0` آن را غیرفعال می‌کند. با Ctrl+C خروجی جزئی ذخیره می‌شود.

Google Translate همچنان ممکن است خطای محدودیت درخواست بدهد؛ تغییر ساختار برنامه این محدودیت سرویس را برطرف نمی‌کند. دریافت همهٔ سایت‌ها هم به دسترس‌پذیری و ساختار فعلی آن‌ها وابسته است.

## شناسهٔ دک

پس از اولین ایمپورت، شناسهٔ دک و مدل را ثابت نگه دار. روشن/خاموش کردن یا جابه‌جایی دیکشنری‌ها ترتیب فیلدهای مدل را تغییر نمی‌دهد؛ شناسهٔ کارت با تغییر محتوا و صوت ثابت می‌ماند. برای ساخت دک مستقل، `deck_id` و نام دک را عوض کن. مدل مشترک می‌تواند بین دک‌های انگلیسی و نروژی مشترک بماند.

تغییرات نسخه‌ها و جزئیات مهاجرت در [یادداشت انتشار](../CHANGELOG.md) آمده‌اند.

در بخش `[sources.lexin]` تنظیم `variant` می‌تواند `"bokmal"`، `"nynorsk"` یا `"both"` باشد. گزینهٔ آخر هر دو منبع را نمایش می‌دهد. بدون این تنظیم، زبان ورودی `nn` از نینوشک و سایر ورودی‌های نروژی از بوکمال استفاده می‌کنند. هر دو در فیلد فعلی Lexin قرار می‌گیرند تا ساختار و شناسهٔ یادداشت‌های Anki ثابت بماند. صوت مطابق گونهٔ زبان ورودی است؛ انتخاب صریح نینوشک از صوت نینوشک استفاده می‌کند.

## کارت‌های تمرینی ترکیبی

پنج ستون مجاور از ستون ورودی: **ورودی | نوع | تگ‌ها | پاسخ | meaning**. اکسل تک‌ستونی یا چهارستونی قبلی همچنان کار می‌کند؛ نوع خالی یعنی `normal`. نام نوع به حروف بزرگ/کوچک حساس نیست.

ستون پنجم معنی دلخواه و اختیاری برای همهٔ نوع کارت‌هاست. اگر پر باشد، بخش با عنوان دقیق `meaning` در ابتدای بخش پاسخِ بک، پیش از دیکشنری‌ها یا پاسخ تمرین نمایش داده می‌شود؛ Info انگلیسی همچنان آخر است. فرمت مستقیم اکسل، از جمله بولد و رنگ بخشی از متن و شکست خط، حفظ می‌شود. ستون خالی یا نبودن آن بخشی ایجاد نمی‌کند. این ستون جایگزین پاسخِ ستون چهارم نمی‌شود و بر مقایسهٔ املا، صوت، کش دیکشنری یا هویت کارت اثر ندارد. فیلدها و شناسهٔ مدل Anki ثابت می‌مانند؛ برای به‌روزرسانی کارت‌ها برنامه را دوباره اجرا و APKG را وارد کن.

در کانفیگ، بخش `[meaning]` با `enabled = false` معنی دلخواه را برای همهٔ نوع کارت‌ها پنهان و با `true` فعال می‌کند؛ مقدار پیش‌فرض کانفیگ‌های قدیمی هم true است. متن اکسل باقی می‌ماند. بعد از تغییر این گزینه، خروجی APKG را دوباره تولید و وارد کن.

برای گوشی‌هایی که فونت‌های ویندوز مثل Calibri را ندارند، نام فونت اکسل همراه جایگزین Vazirmatn نوشته می‌شود. فایل واقعی بولد با وزن ۷۰۰ کنار فونت معمولی در APKG بسته‌بندی می‌شود تا بولد روی اندروید فقط به بولد مصنوعی وابسته نباشد. فونت و مجوز از [مخزن رسمی Vazirmatn](https://github.com/rastikerdar/vazirmatn) هستند. APKG جدید و رسانه‌های آن را وارد/همگام کن. زوم کارت، بزرگ‌نمایی متن سیستم و فونت WebView همچنان می‌توانند اندازه و شکست سطر را تغییر دهند؛ تست مرورگر با اندازهٔ موبایل جای تست روی گوشی واقعی را نمی‌گیرد.

- `normal`: لغت و دیکشنری‌های فعلی؛ ستون پاسخ لازم نیست.
- `type`: سؤال/معنی در ستون اول، لغت مورد انتظار در ستون چهارم؛ مقایسهٔ تایپی Anki و صوت پاسخ پشت کارت.
- `sentence`: جملهٔ سؤال و ترجمهٔ نمونه در ستون چهارم؛ تمرین گفتاری، متن و صوت پشت کارت.
- `gap`: جمله با نشانگر `[…]` یا `[...]` و پاسخ جای خالی در ستون چهارم؛ جملهٔ کامل و صوت پشت کارت.
- `listen`: جملهٔ زبان تمرین در ستون اول و ترجمهٔ اختیاری در ستون چهارم؛ صوت روی فرانت، متن مخفی و سپس متن و صوت پشت کارت.

تگ نوع خودکار اضافه می‌شود. تگ‌های اضافی را با کاما جدا کن؛ فاصله در نام تگ به زیرخط تبدیل می‌شود. در `[cards.normal]`، `[cards.type]`، `[cards.sentence]`، `[cards.gap]` و `[cards.listen]` عنوان، دستور، تگ خودکار و فعال بودن صوت قابل ویرایش‌اند. عنوان و دستور کارت عادی را خالی بگذار تا ظاهر قبلی حفظ شود.

در `[practice]`، `question_language` زبان سؤال و `answer_language` زبان تمرین است؛ مستقل از زبان ترجمهٔ دیکشنری. کدهایی مانند EN، NO، NB، NN و FA پذیرفته می‌شوند. متن راهنما انگلیسی است و `{question_language}` و `{answer_language}` نام زبان‌ها را جایگزین می‌کنند. نام زبان‌های دیگر را در `[practice.language_names]` می‌توان تنظیم کرد. تغییر کانفیگ، محتوای اکسل را ترجمه نمی‌کند. متن پاسخ و کادر تایپ فارسی راست‌به‌چپ‌اند.

صوت تمرین‌های جدید از gTTS و با کش مستقل متن/زبان ساخته می‌شود. برای بوکمال و نینوشک کد صوت عمومی `no` استفاده می‌شود؛ صدای اختصاصی نینوشک ندارد. پخش خودکار تابع تنظیمات مرور Anki است. ضبط یا ارزیابی گفتار نداریم. نوع ناشناخته، پاسخ ضروری خالی و جای خالی بدون نشانگر با شمارهٔ ردیف رد و گزارش می‌شوند. کارت شنیداری بدون صوت نیز رد می‌شود. ردیف یکسان در نوع‌های مختلف حذف نمی‌شود؛ در تکرار دقیق، ردیف اول حفظ می‌شود.

مدل و فیلدها و شناسهٔ کارت عادی ثابت‌اند. چهار مدل مستقل برای تمرین‌ها به همان دک اضافه می‌شوند؛ `practice.model_id_base` را پس از اولین ایمپورت ثابت نگه دار. تغییر پاسخ، هویت تمرین را تغییر نمی‌دهد؛ تغییر سؤال، نوع یا جفت زبان یک تمرین جدید می‌سازد. نیازی به مهاجرت کارت‌های عادی نیست.

فایل CSV معمولی برای تحلیل است. هر خروجی CSV یک فایل `*_anki.csv` هم دارد که ستون نوع یادداشت، تگ‌ها، شناسهٔ GUID و تنظیمات HTML را مشخص می‌کند. ابتدا APKG را وارد Anki کن تا مدل‌های مورد استفاده نصب شوند؛ سپس فایل همراه را در Anki دسکتاپ ۲٫۱٫۵۴ یا جدیدتر وارد کن و دک موردنظر را انتخاب کن. فیلد اول شناسه را تغییر نده. CSV قالب، استایل و صوت را حمل نمی‌کند؛ فایل‌های صوتی باید در `collection.media` موجود باشند. برای ایمپورت کامل، APKG ساده‌تر است. پیش‌نمایش HTML هم سؤال و هم پاسخ را نشان می‌دهد.

آزمون‌ها: `python -m unittest discover -s tests -v` و `python main.py --check`.

تنظیم `input.order = "excel"` ترتیب اکسل را حفظ می‌کند؛ مقدار `"random"` ردیف‌های کامل را پیش از پردازش و خروجی در هر اجرا تصادفی می‌کند. فایل اکسل تغییر نمی‌کند و پاسخ و تگ همراه سؤال می‌مانند. محدودیت `max_words` پیش از تصادفی‌سازی اعمال می‌شود. ترتیب مرور در خود Anki تنظیم می‌شود.

تمرین `gap` با چند جای خالی در یک کارت می‌ماند. در سلول پاسخ، هر جواب را با Alt+Enter در خط جدا و به‌ترتیب جای خالی‌ها بنویس. تعداد جواب‌ها باید برابر باشد و خط پاسخ خالی نباشد؛ در غیر این صورت ردیف رد و گزارش می‌شود. پشت کارت متن کامل با پاسخ‌های برجسته و حفظ خط‌ها نمایش داده می‌شود؛ صوت هم متن کامل را می‌خواند. کل تمرین را خودت یک‌جا نمره می‌دهی. کاما جداکنندهٔ پاسخ‌ها نیست.

روی فرانت `gap` برای هر جای خالی کادر نوشتن وجود دارد؛ نمره‌دهی کل تمرین دستی است. کادر مقایسهٔ بومی `type` در مرور واقعی Anki ظاهر می‌شود و در پنجرهٔ Preview نمایش داده نمی‌شود. برای دریافت تغییرات، برنامه را دوباره اجرا و APKG جدید را وارد کن.

**کیبورد در AnkiDroid:** اگر با لمس جای خالی، کادر فوکوس می‌گیرد ولی کیبورد باز نمی‌شود، گزینهٔ **Settings → Advanced → Workarounds → Type answer into the card** را فعال کن؛ سپس از صفحهٔ مرور خارج شو و دوباره وارد شو. این تنظیم مشکل را روی گوشی اندرویدی آزمایش‌شده برطرف کرد. نام یا محل گزینه ممکن است با نسخهٔ AnkiDroid فرق کند. [راهنمای AnkiDroid](https://docs.ankidroid.org/#_workarounds)

در `[sources.lexin]` با `table_audio = true` صوت تلفظ شکل‌های جدولِ مدخل دقیق اضافه می‌شود. تنظیم کلی صوت هم باید فعال باشد. فایل‌ها کش و همراه دک بسته‌بندی می‌شوند؛ صوت‌های جدول فقط با دکمه پخش می‌شوند. مقدار false جدول را بدون صوت نگه می‌دارد. صوت مثال‌ها و اصطلاح‌ها دریافت نمی‌شود. دریافت صوت‌های جدول از مهلت زمانی همان منبع استفاده می‌کند؛ برای جدول بزرگ می‌توان آن را افزایش داد.

صوت جدول ابتدا از خود Lexin دریافت می‌شود؛ اگر موجود نباشد، پس از انتظار کوتاه از gTTS استفاده می‌شود. شکل‌های جدول خودکار و هم‌زمان پخش نمی‌شوند. کارت type فقط یک مقایسهٔ تایپی بومی دارد که روی پشت کارت از FrontSide به ارث می‌رسد.

پیش از درخواست صوت جدول، هم فایل اصلی Lexin و هم صوت جایگزین gTTS که قبلاً ذخیره شده بررسی می‌شوند. برای شکل بدون فایل، در صورت وجود صوت جایگزین، انتظار سرویس Lexin حداکثر ۱٫۵ ثانیه است؛ اگر تلاش ناموفق باشد، شکل‌های بدون فایلِ باقی‌ماندهٔ همان لغت بدون انتظار تکراری از جایگزین استفاده می‌کنند. فایل اصلی کش‌شدهٔ Lexin همچنان اولویت دارد. آیکون دکمهٔ پخش آرشیو نمی‌شود و عکس واقعی مدخل حفظ می‌شود. کش موجود دیکشنری برای این بهینه‌سازی بی‌اعتبار نمی‌شود.

### سنجش زمان دریافت Lexin

تست زندهٔ مستقل: `python -m tests.benchmark_lexin --label measurement hus hund bil`. دیتابیس موقت و کپی صوت‌های موجود در Output ساخته می‌شود؛ زمان دریافت تازه و استفادهٔ مجدد از کش در `Output/lexin_benchmark_measurement.json` ثبت می‌شود. اکسل‌ها، دیتابیس واقعی و رسانه‌های اصلی تغییر نمی‌کنند. زمان دریافت تازه به شبکه و سرویس صوت وابسته است.

صوت جدول Lexin با دکمهٔ کوچک پخش نمایش داده می‌شود، بدون نوار پلیر و بدون پخش خودکار. متن سؤال و پاسخ کامل gap متناسب با جهت زبان چپ‌چین یا راست‌چین است. متن توضیح «Sample answer…» از پشت کارت گفتاری حذف شده است.

مسیر مشترک مدیا در بالای کانفیگ: در `[media]` مقدار `anki_directory` را مسیر پوشهٔ `collection.media` انکی بگذار. صوت و عکس با حفظ نسخهٔ محلی به آنجا هم کپی می‌شوند؛ صوت کش‌شده و صوت جدول نیز شامل می‌شوند. خالی یعنی کپی غیرفعال. تنظیم قدیمی `audio.copy_to` برای کانفیگ‌های بدون مسیر جدید همچنان پشتیبانی می‌شود.

در نسخهٔ ۵٫۲٫۰ فقط Lexin بوکمال به‌صورت پیش‌فرض فعال است؛ تنظیمات همهٔ منابع دیگر موجود و غیرفعال‌اند. پاسخ کارت تایپی باید تک‌خطی باشد. جهت کادر تایپ مخصوص هر یادداشت است؛ واردکردن زبان دیگر جهت کارت‌های قبلی را تغییر نمی‌دهد. شناسهٔ GUID فایل CSV با APKG یکسان است؛ آن را تغییر نده تا یادداشت‌ها به‌روزرسانی شوند. برای مسیر ویندوز در TOML، اسلش رو به جلو داخل دابل‌کوتیشن یا بک‌اسلش داخل تک‌کوتیشن استفاده کن.

### دیتابیس دائمی دیکشنری‌ها

بخش `[dictionary_cache]` در `config.toml` کش SQLite را در `Cache/dictionaries.sqlite3` فعال می‌کند. نتیجهٔ موفق بر اساس لغت، دیکشنری و تنظیمات مؤثر همان منبع ذخیره و در اجراهای بعد استفاده می‌شود. برای دیکشنری ثابتی مثل Oxford زبان مبدأ انتخاب‌شده دخالت ندارد؛ گونه‌های Lexin جدا می‌مانند. ترجمه به زبان مبدأ و مقصد وابسته است. تغییر تعداد مثال، تعداد عکس یا تنظیمات صوت نتیجهٔ جداگانه دارد. فیلدها و هویت یادداشت‌های Anki تغییر نمی‌کنند.

متن HTML دقیق خروجی کارت، HTML اصلی مدخل دریافت‌شده و نسخهٔ بایت‌به‌بایت رسانه‌های دانلودشده در دیتابیس ذخیره می‌شوند. فایل اصلی عکس‌های جست‌وجوشده هم کنار نسخهٔ کوچک‌شدهٔ کارت نگه داشته می‌شود. عکس و نشانی مستقیم MP3 مدخل اصلی، از جمله تلفظ Oxford، در `Cache/media` هم آرشیو می‌شوند؛ حتی اگر در ظاهر کارت نمایش داده نشوند. صوت تولیدشده با دکمه‌های Lexin و صوت جدول طبق تنظیمات فعال دریافت می‌شود؛ همهٔ کنترل‌های تعاملی سایت خودکار اجرا نمی‌شوند. این آرشیو مدخل‌های دریافت‌شده است، نه نسخهٔ کامل سایت. رسانه‌های صرفاً آرشیوی ظاهر کارت یا اولویت صوت را تغییر نمی‌دهند.

صوت کارت در `[audio].directory`، به‌صورت پیش‌فرض `Audio`، و عکس کارت در `[output].directory/media`، اکنون `Output/media`، قرار دارد. اگر فایل حذف یا تغییر کرده باشد، از نسخهٔ دیتابیس بازسازی می‌شود و برای APKG و کپی اختیاری به `[media].anki_directory` ثبت می‌شود. صوت‌های قبلی قابل استفاده‌اند؛ متن و عکس‌های قدیمی در اولین اجرای موفق پس از این تغییر وارد کش می‌شوند. نتیجهٔ خالی، خطا، پایان مهلت یا دریافت ناقص کش نمی‌شود تا اجرای بعد دوباره تلاش کند. خطای کش با هشدار گزارش می‌شود و مانع دریافت از منبع نمی‌شود.

برای دریافت مجدد `dictionary_cache.refresh = true` بگذار و بعد به `false` برگردان. `enabled = false` کش دیکشنری را غیرفعال می‌کند. مسیرها نسبت به محل `config.toml` هستند. کش محلی است و وارد Git نمی‌شود؛ نسخهٔ پشتیبان فایل SQLite هم متن و هم رسانه‌ها را نگه می‌دارد. نصب سرور یا کتابخانهٔ اضافی لازم نیست.

عکس SVG مدخل هم بدون تبدیل آرشیو می‌شود. خطای آرشیو یک رسانهٔ جانبیِ مدخل مانع کش متن معتبر کارت و رسانه‌های دریافت‌شدهٔ آن نمی‌شود. نشانی فایل ناموفق و خطا در اطلاعات مدخل ذخیره می‌شوند؛ برای تلاش مجدد این رسانه‌های جانبی `refresh = true` بگذار. دریافت ناقص متن دیکشنری یا تلفظ کارت همچنان مانع ذخیرهٔ نتیجهٔ ناقص است.

فایل‌های پایتون برنامه در پوشهٔ `app/` و تست‌ها در `tests/` هستند؛ در ریشه فقط `main.py` فایل پایتون است. اجرا همان `python main.py` است و تست‌ها از ریشه با `python -m unittest discover -s tests -v` اجرا می‌شوند. مسیر کانفیگ، اکسل‌ها، استایل، رسانه‌ها و دیتابیس قبلی تغییر نکرده است.

در فرانت تمرین‌های `type`، `sentence` و `gap` فرمت مستقیم متن اکسل حفظ می‌شود: بولد، ایتالیک، زیرخط، خط‌خوردگی و رنگ فونتِ کل سلول یا بخشی از متن. در XLSX رنگ پس‌زمینهٔ یکدست و اندازه/نام فونت سفارشی هم منتقل می‌شوند؛ برای متن چندفرمتی `openpyxl>=3.1.5` از requirements.txt لازم است. علامت جای‌خالی حتی میان چند بخش با فرمت متفاوت درست تبدیل می‌شود. متن خام سؤال و پاسخ برای تولید صوت، مقایسهٔ املا و هویت یادداشت جدا می‌ماند. متن لیسنینگ در فرانت پنهان می‌ماند و ظاهر کارت لغت معمولی تغییر نمی‌کند. قالب‌بندی شرطی، کادرها و ابعاد جدول اکسل منتقل نمی‌شوند. فایل اکسل ورودی فقط خوانده می‌شود.

برای دیدن دیتابیس، [DB Browser for SQLite](https://sqlitebrowser.org/dl/) را نصب کن؛ با **Open Database** فایل `Cache/dictionaries.sqlite3` را باز کن و در **Browse Data** جدول `results` را انتخاب کن. ستون‌های `word` و `source` لغت و دیکشنری، `content` متن HTML کارت، `sound` صوت، `documents` اطلاعات و HTML اصلی مدخل و `saved_at` زمان ذخیره را نشان می‌دهند. جدول `result_media` نام فایل‌های مرتبط و جدول `assets` نسخهٔ باینری فایل‌ها را نگه می‌دارد. در **Execute SQL** می‌توانی این فهرست را ببینی:

```sql
SELECT word, source, saved_at, sound FROM results ORDER BY source, word;
```

Lexin فقط دو نتیجهٔ اول صفحهٔ ابتدایی را بررسی می‌کند و مدخل‌هایی را نگه می‌دارد که عنوان نروژی‌شان دقیقاً برابر ورودی باشد؛ فاصله‌های اضافی، تفاوت حروف بزرگ/کوچک و شکل معادل یونیکد یکسان‌سازی می‌شوند. نتیجهٔ سوم به بعد و صفحات بعدی بررسی نمی‌شوند. معنی، مثال و جدول هر مدخل پذیرفته‌شده حفظ می‌شود؛ تطبیق صرفاً در ترجمهٔ انگلیسی یا کلمهٔ مرکب کافی نیست. یک تلفظ لغت روی فرانت استفاده می‌شود و صوت جدولِ فعال برای مدخل‌های پذیرفته‌شده پردازش می‌شود. کش موجود Lexin، حتی نتیجه‌های تک‌مدخلیِ قدیمی، بدون دریافت مجدد قابل استفاده است. برای دریافت دو مدخل یک لغت قدیمی، فقط کش همان لغت را با دستورهای زیر پاک کن.

### پاک‌کردن کش یک لغت

حذف کش همهٔ گونه‌ها و تنظیمات یک لغت، بدون اجرای اکسل یا مراجعه به سایت:

```powershell
python main.py --clear-cache hus --source lexin
python main.py --clear-cache hus
```

دستور اول فقط Lexin و دومی همهٔ منابع همان لغت را پاک می‌کند. مسیر دیتابیس از کانفیگ خوانده می‌شود، حتی اگر کش غیرفعال باشد. رکوردهای رسانهٔ مرتبط و پشتیبان‌های باینری بدون استفاده از دیتابیس حذف می‌شوند؛ فایل‌های صوت و عکس محلی باقی می‌مانند. اجرای عادی بعدی نتیجهٔ دیکشنری حذف‌شده را دوباره می‌گیرد.

### نگهداری دستی با SQL

در DB Browser هم می‌توانی از **Execute SQL** حذف کنی؛ برای جلوگیری از رکوردهای رسانهٔ بدون نتیجه، این دستورها را با هم اجرا کن و **Write Changes** را بزن:

```sql
BEGIN;
DELETE FROM result_media WHERE key IN (
  SELECT key FROM results WHERE source = 'lexin' AND lower(trim(word)) = 'hus'
);
DELETE FROM results WHERE source = 'lexin' AND lower(trim(word)) = 'hus';
DELETE FROM assets WHERE NOT EXISTS (
  SELECT 1 FROM result_media WHERE result_media.digest = assets.digest
);
COMMIT;
```

دستور خط فرمان یکسان‌سازی کامل یونیکد را هم انجام می‌دهد؛ SQL بالا مثال سادهٔ لغت انگلیسی‌نویس `hus` است. بعد از ذخیره، DB Browser را ببند و سپس برنامه یا دستور حذف کش را اجرا کن.
